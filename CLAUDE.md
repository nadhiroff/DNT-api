# NovaBase — notes pour les agents

- Cahier des charges : clone Supabase en PHP 8.3 natif + MySQL 8, livré **phase par phase** ; attendre la validation de l'utilisateur avant la phase suivante.
- Avant toute livraison : `composer check` (PHPStan niveau 8 sans erreur + PHPUnit vert). Intégration MySQL : `NB_TEST_DB_USER` / `NB_TEST_DB_PASSWORD`.
- SQL uniquement dans `app/Repositories` (ou Migrator/commandes d'infrastructure), toujours paramétré ; identifiants via `Identifier::quote()`. `tests/Unit/SqlSafetyTest.php` refuse toute concaténation de variable.
- Gabarits : toute sortie via `e()` ou un helper `$this->…` de `Template` ; pas d'attribut `style`, pas de script sans nonce (CSP stricte). Couleurs via jetons sémantiques (`docs/design-system.md`).
- Assets : `npm run build` après toute modification de `resources/` ou de classes Tailwind dans `views/` ; les fichiers compilés sont versionnés.
- Configuration : `config/env.php` (tableau PHP, pas de `.env` : l'hébergeur ne les accepte pas). Les fichiers de `config/` commencent par la garde `NOVABASE_ROOT`.
- Installation possible en sous-dossier sans réécriture (Apache local `AllowOverride None`, `http://localhost/DNT-api/`) : générer toutes les URL via `UrlGenerator` / `$this->url()` / `$this->asset()`, jamais en dur.
- MySQL local : compte `admin` (migrations/provisioning/tests), `novabase_app` (applicatif). Tests d'intégration : `NB_TEST_DB_USER=admin NB_TEST_DB_PASSWORD=Admin`.
- Échec CSRF = 403 `csrf_token_mismatch` (pas 419 : Apache transforme les statuts non standard en 500).
- Parcours HTTP testés dans `tests/Integration/AuthFlowTest.php` (session en mémoire, e-mails en fichiers) : y ajouter chaque nouveau parcours web.
- Deux rôles seulement : `user` et `superadmin` (pas de rôle `admin`). Espace `/admin` protégé par `RequireSuperadmin` (404 pour les autres). 2FA obligatoire pour le superadmin.
- Témoignages de la page d'accueil gérés en base (`testimonials`, `site_settings`) depuis `/admin` ; jamais de faux témoignages publiés (les exemples restent en brouillon).
- Console : `layouts/app.php` (barre latérale, entrée active = plus long préfixe), en-têtes via `components/page-header` (bouton retour sur les pages de détail), toasts = `components/alerts`, confirmations = `data-confirm` sur le formulaire (jamais `alert/confirm/prompt`, testé).
- Styles en ligne interdits (CSP) : largeur des jauges via `data-percent` ; graphiques Chart.js via `data-chart` + `resources/js/charts.js` (couleurs `--nb-chart-1/2` validées).
- Projets : `ProjectProvisioner` (compte admin MySQL) ; DDL avec `Identifier::quote()` / `Identifier::literal()` uniquement. Tests de parcours : `tests/Integration/WebTestCase.php`.
- Données des projets : `ProjectDataService` (CRUD, filtres en liste blanche), `DynamicTableService` (DDL avec l'utilisateur MySQL du projet, verrou par projet, `schema_changes`), `AccessPolicy` (règles par table). Identifiants utilisateur validés par `Identifier::problem()`.
- Éditeur SQL (`/projects/{ref}/sql`) : `SqlEditorService` exécute avec l'utilisateur MySQL du projet (droits = sécurité), refuse USE/LOCK/transactions/SLEEP, puis `SchemaSync` aligne `table_definitions` sur la vraie structure (tables avec `id` AUTO_INCREMENT ou CHAR(36) ; ajoute owner_id/created_at/updated_at). Lire information_schema avec le nom de base explicite, jamais DATABASE().
- E-mails : SMTP en base (`SmtpService`, global puis par projet, repli env.php), modèles plateforme dans `EmailTemplates` + table `email_templates`, API `POST /email/send` via `SendProjectEmailJob`.
- Clés API : hash pour l'authentification + copie chiffrée (`key_enc`) pour la copie dans la console ; types `public`/`secret` uniquement, droits automatiques.
- Messages, commentaires et textes d'interface en français.
